# Hooks, angles and generic-content traps

Read in Step 4 (strategy) of the workflow, before drafting.

## Choose the angle first

A source usually holds several possible posts. Find the distinct angles, then pick one.

| Angle | Question it answers | Works when the source has |
|---|---|---|
| Contrarian | What does everyone believe that this contradicts? | A claim against common advice, backed by evidence |
| Outcome | What changed, by how much? | A result with a number or a before and after |
| Story | What happened, and what did it cost? | A real sequence of events with stakes |
| How-to | What exact steps worked? | Specific, repeatable steps |
| Framework | What is the model for thinking about this? | A named structure or list that explains a felt problem |
| Reaction | What is this a response to? | A triggering claim, event or quote |

If two angles are both strong and the choice changes the output, ask the user in one line each. If one is clearly stronger, use it and say which.

## Match the hook to the content shape

This is a starting point. When unsure, lead with the most surprising or specific element of the source.

| Content shape | Hook type | Pattern |
|---|---|---|
| Data or research | Outcome first, or contrarian | State the surprising conclusion, then the evidence |
| Personal story | Tension first | Establish the stakes before the story |
| Tactical how-to | Specificity | Name the exact result and the exact method |
| Opinion | Direct assertion | Say it flat. Do not soften with "I think" or "might" |
| Curated list or framework | Curiosity gap | Imply the list solves a problem the reader already feels |
| Interview or conversation | Quote first | Open with the single most surprising line, attribute second |
| Myth-busting | Name the belief, then break it | "Everyone says X. The data says Y." |
| Retrospective | Time anchor plus stakes | "Three years ago I made the most expensive mistake of my career." |
| Trend or prediction | Stakes | What happens to the reader if they miss it |
| Case study | Outcome first | Lead with the result so the reader wants the story |

Every hook must come from the source. Do not invent a number or an experience to make a hook stronger. If the source has no outcome, do not write an outcome hook.

## The hook test

Remove the hook and ask whether the reader can still predict the value of the piece. If yes, the hook is not doing its job. Then read it as a stranger: would you stop?

Failure modes by platform:

- X: a first post that needs context to make sense.
- LinkedIn: a first line that fills the space before "see more" without earning it.
- TikTok and Shorts: any greeting or "in this video". Viewers decide in the first seconds.
- Shorts: a hook that promises more than the ending delivers.
- Instagram: a title slide in place of a claim.

## Hook variants

When the user asks for hook options, produce 3 to 5 that differ in type, not in wording. Label each with its type from the table, keep each inside the platform's visible-text limit, and recommend one with a one-line reason. Do not present a variant as better "for reach". There is no evidence a hook type wins on every platform.

## Generic-content traps

Fix these while drafting. Surface one only when you cannot fix it without more information.

- Hollow openers: "In today's fast-paced world", "It's no secret that", "As we navigate".
- Vague superlatives with no evidence: "groundbreaking", "game-changing". Replace with the number, name or outcome behind it.
- Bullet lists by default. Use bullets only when the content is list-shaped.
- Generic calls to action: "Check out the link below", "Don't miss out". Name what the reader gets.
- Summarising when you should select. Two ideas covered well beat six covered thinly.
- Passive hooks: "It has been found that". Use an active subject.
- Swappable text: if the piece could be about any company or person in the field, it fails. Add the specific detail or flag that the source lacks one.

## Pre-draft checks (silent)

1. Specificity. Name one detail only this source has. If you cannot, tell the user the output will read as generic and ask if they have more.
2. Reader. Name the one person who most needs this. "A first-time founder who just hired their first employee" beats "entrepreneurs".
3. Hook bet. Would the first line stop your scroll as a stranger?
